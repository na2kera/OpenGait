# 日本語でのPR作成

リポジトリ内の PR テンプレート、CONTRIBUTING、既存 PR の慣習を最初に確認し、それらがあれば優先する。

## 作成手順

1. 差分、関連 issue、実行したテストを確認する。不明な内容を推測で補わない。
2. タイトルを日本語で一文にする。変更対象と目的が分かる簡潔な表現にし、必要なら先頭に既存の種別ラベルを付ける。
3. 説明文を日本語で書く。テンプレートがなければ、原則として次の見出しを使う。

   ```markdown
   ## 背景

   ## 変更内容

   ## 影響範囲

   ## 確認内容
   ```

4. `変更内容` には実際の変更を箇条書きで、`確認内容` には実行済みのコマンドと結果を記す。未実施の確認は「未実施」と理由を明記する。
5. 固有名詞、API 名、コード、コマンド、ファイル名は原表記のままにする。それ以外の説明、見出し、箇条書きは日本語にする。
6. 作成・更新前に、タイトルと本文が差分と一致し、レビュー担当者が背景・変更・影響・検証を追えることを確認する。

## 表現の基準

- 曖昧な「対応しました」は避け、何をどう変えたかを書く。
- 実装の細部を羅列するより、レビューに必要な意図と挙動を優先する。
- 破壊的変更、移行手順、既知の制約があれば独立して明記する。
- PR 作成ツールの既定文が英語でも、タイトルと説明文は日本語で入力する。
